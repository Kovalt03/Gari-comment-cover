# Gari

댓글을 내 기준으로 가려주는 크롬 확장입니다. 지우지 않고 가립니다.
뭘 가릴지는 제가 아니라 쓰는 사람이 정합니다.

> [English](README.md) · **한국어**
> 만드는 중이고, 아직 설치할 수 있는 빌드는 없습니다.

## 뭘 만들고 있나

유튜브 댓글창을 열었을 때, 보고 싶지 않은 댓글이 눈에 스치기 전에 접어두는 확장입니다.
뭐가 "보고 싶지 않은 댓글"인지는 쓰면서 배웁니다. 댓글을 접을 때마다 그 취향이 쌓입니다.

판정은 전부 쓰는 사람 컴퓨터 안에서 일어납니다. 댓글이 서버로 나가지 않습니다.

## 왜

댓글에 섞여 있는 건 대충 세 종류입니다.

1. 스팸. 광고, 링크 유도, 반복 게시
2. 불쾌한 것. 인신공격, 과한 언쟁
3. 그냥 내가 보기 싫은 것. 스포일러, 특정 주제, 지겨운 밈

세 번째 때문에 만듭니다. 앞의 둘은 기준이 어느 정도 정해져 있지만, 세 번째는 사람마다 다릅니다.

지금 있는 도구들로는 세 번째가 안 됩니다.

- 유튜브 기본 차단 단어는 채널 주인용이라 시청자는 쓸 수 없습니다.
- uBlock Origin 사용자 규칙은 키워드나 CSS 셀렉터라서 맥락을 못 보고, 규칙도 직접 써야 합니다.
- 댓글 차단 확장들은 키워드 매칭이거나 아예 통째로 숨기는 식입니다. 개인화가 없고 오탐이 많습니다.

전부 키워드거나 전체 차단입니다. 맥락을 안 보고, 사람마다 달라지지도 않습니다.

그래서 세운 가설이 이겁니다. 문장 임베딩으로 댓글 의미를 벡터로 만들고 사용자가 접은 댓글들과의
유사도를 학습하면, 키워드로는 안 잡히는 "이 사람이 싫어할 댓글"을 골라낼 수 있지 않을까.
이게 맞는지 확인하는 게 사실상 이 프로젝트의 전부입니다.

## 어떻게

### 일단 다 숨기고 시작한다

제일 중요한 건 정확도보다 타이밍입니다. 불쾌한 댓글이 한 번이라도 눈에 스치면 이 확장을 쓸 이유가 없어집니다.

```
document_start 에 CSS 주입 → 댓글 영역 전부 숨김
        ↓
MutationObserver 로 댓글 노드 삽입 감지
        ↓
필터 파이프라인
        ↓
통과한 것만 순서대로 표시
```

판정하고 나서 숨기는 게 아니라, 숨겨둔 채로 시작해서 통과한 것만 보여주는 구조입니다.
기본값이 숨김이라 파이프라인이 느리거나 죽어도 불쾌한 댓글이 새어나오지 않습니다.

대신 파이프라인이 죽으면 아무것도 안 보입니다. 그래서 타임아웃이 지나면 숨김은 유지하되
"필터가 실패했어요, 그냥 볼까요?" 배너를 띄워서 직접 고르게 할 생각입니다.

### 무거운 판단은 거의 안 한다

댓글 하나마다 LLM을 부르는 건 불가능합니다. 영상 하나에 댓글이 수백 개고, 스크롤할 때마다 계속 불러옵니다.
그래서 판정을 네 단계로 나눴습니다.

| 단계 | 방식 | 목표 지연 | 여기서 처리하고 싶은 비율 |
|---|---|---|---|
| L0 | 캐시 조회. 이미 판정한 댓글 | 1ms 미만 | 다시 볼 때는 대부분 |
| L1 | 규칙. 정규식, 링크, 반복 문자, 금지어 | 1ms 미만 | 30~50% |
| L2 | 로컬 임베딩 모델 + 가벼운 분류기 | 10~50ms (배치) | 45~65% |
| L3 | LLM 재판정. 애매한 것만 | 수백 ms | 5% 미만 |

정확도를 유지하면서 L3 호출을 얼마나 줄이느냐, 이 수치가 이 프로젝트의 핵심 결과물이 될 겁니다.

### 쓸수록 내 기준에 맞춰진다

댓글을 접으면 그 임베딩이 "싫어함" 프로필에 쌓이고 다음 판정에 반영됩니다.
처음엔 라벨이 없으니 스팸, 욕설, 스포일러 같은 기본 카테고리로 시작하고,
기록이 쌓이면 개인 프로필 쪽 가중치를 올립니다.
사이트마다 댓글 성격이 다르니 프로필은 사이트별로 따로 둡니다.

## 구조

```
+----------------------------------+
|  Site Adapter                    |   사이트마다 하나씩
|                                  |
|  find comment nodes              |
|  extract text                    |
|  hide / reveal                   |
+----------------------------------+
                 |
                 |  interface
                 |
+----------------------------------+
|  Core                            |   사이트를 모름
|                                  |
|  pipeline  L0 -> L1 -> L2 -> L3  |
|  embedding engine (ONNX)         |
|  user profile                    |
|  cache / storage (IndexedDB)     |
+----------------------------------+
```

Core는 DOM을 모릅니다. 텍스트랑 ID만 받습니다. 덕분에 브라우저 없이 테스트할 수 있습니다.
DOM을 아는 코드는 전부 어댑터 안에 있어서, 유튜브가 구조를 바꾸면 그 파일만 고치면 됩니다.

기술 스택은 아직 잠정입니다.

- Manifest V3 + TypeScript, 빌드는 Vite 아니면 esbuild
- 추론은 ONNX Runtime Web. WebGPU 쓰고, 안 되는 환경에서는 WASM으로
- 모델은 다국어 문장 임베딩 20~100MB 급에서 고를 예정
- 저장은 IndexedDB
- L3는 Chrome Built-in AI를 보고 있는데 가용성 확인이 필요하고, 폴백은 필수

## 원칙

검열 도구가 아니라, 자기 피드를 자기가 조정하는 도구입니다.

- 뭐가 나쁜 댓글인지 제가 정하지 않습니다. 쓰는 사람이 정합니다.
- 지우지 않고 접습니다. 언제든 다시 펼칠 수 있습니다.
- 왜 접었는지 이유를 보여줍니다. 판정이 틀렸다는 걸 알 수 있어야 하니까요.
- 데이터는 전부 로컬에 있고 밖으로 나가지 않습니다. L3에서 외부 API를 쓰게 되면 그때 따로 동의를 받습니다.
- 유튜브 계정은 건드리지 않습니다. 차단도 신고도 안 합니다. 내 화면 안에서만 일어나는 일입니다.

하나 더. 재현율보다 정밀도를 우선합니다.
못 걸러낸 댓글은 사용자가 접으면서 알려주지만, 잘못 걸러낸 댓글은 알려줄 기회조차 없습니다.
좋은 댓글이 소리 없이 사라지기 시작하면 그때부터 이 도구를 못 믿게 됩니다.
