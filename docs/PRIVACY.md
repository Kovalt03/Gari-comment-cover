# 데이터 처리

이 확장은 사용자가 보는 모든 댓글을 읽는다.
그래서 무엇을 읽고, 무엇을 저장하고, 무엇을 저장하지 않는지를 명시한다.

## 1. 원칙

- 댓글 텍스트는 기기를 벗어나지 않는다
- 저장은 필요한 최소한으로 한다. 원문은 보관하지 않는다
- 작성자를 식별할 수 있는 정보는 수집하지 않는다
- 데이터 수집을 수반하는 기능은 기본으로 켜지 않는다

## 2. 읽는 것

판정을 위해 다음을 읽는다.

- 댓글 본문 텍스트
- 사이트 내에서 댓글을 구분하기 위한 식별자
- 현재 페이지의 식별자 (댓글 캐시를 페이지 단위로 다루기 위함)

읽기만 하고 저장하지 않는 항목은 판정이 끝나는 시점에 메모리에서 사라진다.

## 3. 저장하는 것

모두 확장 origin의 IndexedDB에 저장된다. 사용자 기기 안에만 존재한다.

| 저장소 | 내용 | 원문 포함 여부 |
|---|---|---|
| `verdicts` | 댓글 텍스트의 해시, 판정 결과, 판정한 계층 | 없음 |
| `profile` | 사이트별 임베딩 벡터와 누적 횟수 | 없음 |
| `metrics` | 계층별 처리 건수와 지연 분포 | 없음 |
| `settings` | 민감도, 카테고리 on/off, 실패 시 동작 | 해당 없음 |

`verdicts`는 같은 댓글을 두 번 판정하지 않기 위한 캐시다.
키로 해시를 쓰므로 저장된 값에서 원래 문장을 복원할 수 없다.

`profile`은 사용자가 접은 댓글의 임베딩을 누적한 것이다.
임베딩은 고정 길이 실수 벡터이고 원문으로 되돌릴 수 없다.
다만 의미가 비슷한 문장과의 유사도는 계산할 수 있으므로, 취향 자체는 이 데이터에 담긴다.
외부로 내보내지 않는 이유가 여기에 있다.

## 4. 저장하지 않는 것

- 댓글 원문
- 작성자 이름, 채널 주소, 프로필 이미지
- 시청 기록, 방문한 영상 목록
- 계정 정보

작성자 관련 항목은 저장하지 않는 수준이 아니라 추출 단계에서 읽지 않는다.
어댑터가 DOM에서 뽑아내는 것은 본문 텍스트와 식별자뿐이다.

## 5. 외부 전송

기본 구성에서 외부로 나가는 요청은 없다.
판정은 전부 기기 안에서 끝나고, 서버를 두지 않는다.

예외가 될 수 있는 경로는 두 가지이며 둘 다 기본값이 아니다.

- 브라우저 내장 모델(Chrome Built-in AI)을 쓰는 경우.
  추론은 기기에서 일어나지만 모델 파일 다운로드에는 네트워크가 필요하다.
  다운로드를 사용자 동의 없이 시작하지 않는다
- 외부 LLM API를 쓰는 경우. 댓글 텍스트가 기기를 벗어나므로 별도의 명시적 동의를 받는다.
  동의하지 않으면 해당 계층 없이 동작한다 (미결정: 이 경로를 지원할지 자체가 정해지지 않았다)

## 6. 권한

`host_permissions`는 실제로 동작하는 사이트로만 한정한다.
모든 사이트에 대한 접근 권한을 요청하지 않는다.

새 사이트를 지원할 때마다 권한이 하나씩 늘어나며, 목록은 `manifest.json`에서 확인할 수 있다.

## 7. 사용자 통제

- 저장된 모든 데이터를 삭제할 수 있다
- 학습된 프로필만 따로 초기화할 수 있다. 판정 기준을 처음부터 다시 만들고 싶을 때 쓴다
- 확장을 삭제하면 저장된 데이터도 함께 사라진다

접힌 댓글은 삭제되지 않는다. 언제든 펼칠 수 있고, 접힌 이유가 함께 표시된다.

## 8. 개발 과정에서 수집하는 데이터

모델 평가를 위해 개발자가 별도로 댓글을 수집한다. 이는 확장의 동작과 무관하며 저장소에 포함될 수 있다.

수집 항목은 댓글 텍스트, 영상 식별자, 좋아요 수, 작성 시각, 부여한 라벨이다.
작성자 이름과 채널 링크는 수집 단계에서 제외한다.

저장소에 포함되는 평가셋에도 같은 규칙이 적용된다.
